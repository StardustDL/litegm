# litegm v3 规划

> 基于 2026-10-24 的 v1 / v1.5 / v1.6 / v2 / v2.1 实现现状整理。
> 当前已具备：图像（生成/编辑/通用模型）、视频（OpenAI 异步协议 + 任务族）、音频（异步扩展）、
> 管理台（历史/详情/输入图/队列）、鉴权、回退链、提交前校验、429 背压。
>
> **状态（2026-10-24）**：P0 全部完成；P1 全部完成；三项前端需求完成。
> 唯一延期项：ComfyUI `/ws` 真实步级进度 → **v4**（用户决定）。v3 采用按阶段/耗时的
> 进度估算作为替代，见 `docs/changelog/v3-ops-and-ui.md`。

### 尚未完成（v2 规划中列出但没做的）

| 编号 | 项 | 影响 |
|------|----|------|
| P1-1 | 配置热载（不重启增删模型/后端） | 运维体验；当前改配置必须重启 |
| P1-2 | Docker 化 | 部署形态；v1 只支持本地运行 |
| P1-3 | 存储治理（磁盘上限/LRU/分级保留） | 长期运行风险：`artifact_ttl_days` 之外无容量控制 |
| P1-4 | 可观测性（结构化日志/`/metrics`/liveness-readiness） | 排障与监控 |
| P1-5 | 管理台增强（prompt 搜索、导出、重跑、队列可视化） | 使用效率（时间范围过滤已有） |

### 代码审阅新发现的问题（v3 需要处理）

| 编号 | 问题 | 证据/说明 | 严重度 |
|------|------|-----------|--------|
| N1 | **长任务的进度不可靠** | 视频/音频进度只能停在 50%（`/queue` 无法给出步级进度），且任务失败后进度会回退到 5/10（`_finish` 未保留进度） | 中 |
| N2 | **同步超时后无法从 OpenAI 客户端取回** | 图像 504 时任务继续，但只有非标 `GET /v1/tasks/{id}` 能取回；OpenAI SDK 调用方需自行重试（会重复生成） | 中 |
| N3 | **`stream=true` 的图像 SSE 语义不完整** | 只在完成时发一个 `image_edit.completed`，没有 `partial_image`（ComfyUI 无中间帧） | 低 |
| N4 | **管理台删除/清理缺失** | 只有取消/重试；没有删除任务与产物、没有批量清理 | 低 |
| N5 | **`n` 多图串行执行，长任务放大** | `n=4` 视频编辑要跑 4 次；目前无并发上限之外的提示 | 低 |
| N6 | **失败任务不清理输入图** | `input_images` 与 `uploads/` 长期累积 | 低 |
| N7 | **无审计日志的敏感信息脱敏** | prompt 全文入库（这是有意为之），但错误信息里可能带本机路径 | 低 |
| N8 | **无配置 schema 版本/迁移提示** | 配置字段增加时旧配置可能静默失效（当前 pydantic 默认值会掩盖） | 低 |

## 2. v3 候选范围（按优先级）

> 已确认：v3 = P0 + P1，另加三项前端需求（见 P1-7/8/9）。热载边界按 D4 建议
> （仅 tasks/routing/backends），进度接 ComfyUI `/ws`（已验证可用）。

### P0：稳定性与运维基础（先做）

1. **存储治理（P1-3 + N6）**：`storage.max_bytes` 磁盘上限、LRU 清理、失败任务产物与输入图的分级保留（失败任务保留更久）、手动清理接口与按钮。
2. **可观测性（P1-4）**：请求级结构化日志（request_id/task_id/耗时/状态）、`/metrics`（任务计数、耗时直方图、后端队列、磁盘用量）、`/health/live` 与 `/health/ready` 分离。
3. **配置热载（P1-1）**：`POST /admin/api/config/reload`（校验失败回滚）、`litegm check --watch`；仅热载 `tasks`/`routing`/`backends`，`server`/`auth`/`storage` 变更需重启（接口会明确提示）；进行中任务保持提交时的配置快照。
4. **修复 N1（进度）**：接入 ComfyUI `/ws`（`progress`/`executing`/`execution_error`）推进真实进度并支持断线退避重连；失败时保留最后进度。

### P1：部署、使用体验与前端

5. **Docker 化（P1-2）**：多阶段构建（web → runtime），micromamba 安装 pixi 环境，compose 挂载 `config/`、`data/`，密钥走环境变量；不改代码结构。
6. **管理台增强（P1-5 + N4）**：prompt 关键词搜索、导出 CSV/JSON、同参数重跑、删除任务（硬删产物 + 软删记录）、队列可视化。
7. **前端媒体预览（新需求）**：图片、视频（`<video>`）、音频（`<audio>`）在任务详情与 Playground 结果区**内联播放/查看**，不再直接触发下载；提供"下载原文件"作为次要操作。
8. **前端视觉重构（新需求）**：改为**浅色调**主题，重做布局（左侧导航 + 主内容区）、配色与排版，提升可读性与信息密度；保持响应式。
9. **前端 Playground（新需求）**：页面内直接提交任务——按任务类型（图像生成/编辑、视频、音频）动态生成表单（模型/提示词/尺寸/时长/参数），支持上传参考图，提交后展示任务进度与产物预览（复用第 7 项）。

### P2：能力扩展（v3 不做，留待 v4）

10. **`mask` 局部重绘（P2-1）**：新增 mask workflow 变体，配置 `mask_policy: supported`。
11. **img2img / 放大（P2-2）**：新增 task 类型 `image.img2img`、`image.upscale`。
12. **多后端调度（P2-3）**：`tags` 能力匹配、跨后端故障转移。
13. **提示词模板（P2-4）**：`prompt_template` 结构化包装。
14. **参考视频/音频（可选）**：需先解决 R2V 模板的 VIDEO→IMAGE 转换。

## 3. 已确认的决策

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | v3 范围 | **P0 + P1 + 三项前端需求**；P2 留待 v4 |
| D2 | Docker 基础镜像与安装方式 | 运行阶段用 `ghcr.io/prefix-dev/pixi:0.83.0`，按 `pixi.lock` 安装（Python 3.15） |
| D3 | `/metrics` 是否引入 Prometheus 客户端库 | 自实现文本格式，不引依赖 |
| D4 | 配置热载边界 | 仅热载 `tasks`/`routing`/`backends`；`server`/`auth`/`storage` 需重启（接口明确返回需重启字段） |
| D5 | 进度事件方案 | **v3 不做 `/ws`，改按阶段/耗时估算；`/ws` 真实步级进度放 v4** |
| D6 | 多后端调度 | 放 v4 |
| D7 | 删除语义 | 硬删产物 + 软删任务记录（保留审计） |
| D8 | 免认证模式 | 新增 `auth.enabled` / `LITEGM_AUTH_DISABLED`，仅用于本地开发与截图 |

## 6. 验收方式

- 每个里程碑写 changelog。
- 测试仍用"小尺寸/短时长"样本，避免长时间占用 GPU。
- 运维类功能用真实运行中的网关验证（例如制造一次磁盘超限、触发一次热载回滚、拉取一次 `/metrics`）。
- 协议兼容性继续用官方 OpenAI SDK 实测。
