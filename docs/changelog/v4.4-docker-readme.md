# v4.4 container build: ship README.md and LICENSE for the editable wheel

## Motivation

`docker compose up --build` failed while pixi installed the project's own PyPI
package:

```
× failed to update PyPI packages for environment 'default'
├─▶ Failed to prepare distributions
├─▶ Failed to build `litegm @ file:///app`
╰─▶ Call to `hatchling.build.build_editable` failed (exit status: 1)
     OSError: Readme file does not exist: README.md
```

`pyproject.toml` declares `readme = "README.md"` and
`license-files = ["LICENSE"]`, and `[tool.pixi.pypi-dependencies]` installs
`litegm` from the build directory as an editable package. hatchling validates
those metadata fields while building the editable wheel, so the build directory
must contain both files. The `runtime` stage only copied `pixi.lock`,
`pyproject.toml` and `src/`, so hatchling could not find `README.md` in `/app`.

The failure was not visible locally: `pixi install` runs from the repository
root, where both files already exist, and existing local environments already
hold the editable install.

The preceding `run-post-link-scripts = false` warnings are unrelated; they are
printed by pixi for conda packages and are not the cause of the failure.

## Changes

- `Dockerfile`: the environment stage now copies `README.md` and `LICENSE`
  together with `pixi.lock`/`pyproject.toml`, with a comment explaining why
  hatchling needs them.

## Verification

- The two files are present at the repository root and are not excluded by
  `.dockerignore`, so they are available to the build context.
- A full `docker compose up --build` was run by the operator on the deployment
  host after the change; the image builds and the container starts.

## Known limitations

- The image build still requires network access to conda-forge/PyPI; registry
  mirrors can be passed via `NODE_IMAGE`/`PIXI_IMAGE` as documented in the
  `Dockerfile` header.
