# v4.7 MiniMax H3 Image: text-to-image and image editing in the example configuration

## Motivation

The deployment backend already serves MiniMax H3's image model, but the shipped
example configuration only covered Qwen Image 2.1, MOSS and the H3 video/music
aliases. Users of a fresh checkout therefore could not reach H3 Image through the
gateway without writing templates themselves. This milestone adds it the same way
every other model is added: as configuration plus API-format templates, with no
gateway code changes.

## Changes

- `config/workflows/minimax_h3_image_t2i_api.json` (new): text-to-image. UNET
  `minimax_h3_image_pruned_int8_convrot`, CLIP `qwen3vl_32b_minimax_h3_nvfp4_awq`
  (`type: minimax`), VAE `minimax_h3_image_vae_fp16`; `MiniMaxH3ImageConditioning`
  produces both the conditioning and the empty latent, sampled with BasicGuider +
  BasicScheduler + SamplerCustomAdvanced and saved via `SaveImageAdvanced`.
- `config/workflows/minimax_h3_image_edit_api.json` (new): image editing. The same
  weights with the H3 image VAE wired into `MiniMaxH3ImageConditioning` and
  uploaded images on `images.image_1`/`images.image_2`; `width`/`height` are 0 so
  the canvas follows the first input image.
- `config/litegm.yaml`:
  - `tasks.image.generate` → `minimax-h3-image` (32-pixel grid, 256–4096 edges,
    1024x1024 default, `quality` → steps 12/24/40, prefix, seed, steps injected).
  - `tasks.image.edit` → `minimax-h3-image` (target slot `20`, optional reference
    chain from `21` with `extra_node_base: 22`, encoder node `4`, `mask_policy:
    unsupported`, size follows the input image).
  - `routing.unified_image_models` → `minimax-h3-image`, so one alias serves both
    operations and `POST /v1/images` routes by whether images are supplied.
- `docs/usage.md`: the built-in alias table lists `minimax-h3-image` with its
  `<Picture 1>`/`<Picture 2>` prompt convention and the required weights/nodes.
- The alias stays entirely in the tracked example configuration; no host address,
  backend id or `.config/` path from the local test deployment leaks into it.

## Known limitations

- H3 Image takes no negative prompt and no CFG (`BasicGuider`, cfg 1); `quality`
  only changes the step count.
- Image references in the prompt must use `<Picture N>`, not the `<imageN>` form
  used by the Qwen edit templates.
- Masks are unsupported, and an explicit `size` on the edit route is advisory
  only (the canvas follows the input image), matching the existing Qwen edit
  variants.
- The alias requires H3 image weights and the `MiniMaxH3ImageConditioning` node
  on the target backend; on a backend without them the alias fails pre-submit
  validation while other models keep working.
