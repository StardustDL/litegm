# v4.1 ffmpeg in the container image

## Motivation

The admin console already extracts video first frames with `ffmpeg` when the
binary is on `PATH` (`src/litegm/admin.py`), but the production image did not
ship it, so video artifacts always fell back to the neutral placeholder frame.
Installing `ffmpeg` ad hoc in the runtime stage would have made the image drift
from `pixi.lock`; declaring it in the pixi environment keeps the image, the
local development environment and the lock file identical.

## Changes

- `pyproject.toml`: `ffmpeg` added to `[tool.pixi.dependencies]` of the default
  environment (`>=9.0.2,<10`, conda-forge, linux-64 + linux-aarch64 + win-64).
  The `dev`/`web` feature environments inherit the default dependencies, so local
  development and tests see the same binary.
- `pixi.lock`: re-locked with `pixi add ffmpeg` (ffmpeg 9.0.2 + its codec
  libraries, ~100 packages per Linux platform).
- `Dockerfile`: after `pixi install --locked`, the build runs
  `pixi run ffmpeg -version` and `pixi run ffprobe -version`, so a missing or
  broken binary fails the image build instead of surfacing as placeholder
  thumbnails at runtime.
- `README.md`, `docs/usage.md`, `docs/development.md`: note that the runtime
  environment and the image include `ffmpeg`/`ffprobe`, and that video
  thumbnails no longer depend on a host-side install.

## Verification

- `pixi add ffmpeg --no-install` resolved `ffmpeg 9.0.2` for `linux-64`,
  `linux-aarch64` and `win-64`; the lock file is the only dependency artefact
  changed.
- Unit tests (`pytest -q -m "not integration"`) still pass; the existing
  thumbnail tests cover both the ffmpeg-present and ffmpeg-absent paths by
  monkeypatching `admin._find_ffmpeg`, so they do not require the binary.
- `scripts/fix_utf8.py` and `scripts/check_doc_links.py` report OK for the
  edited documents.

## Known limitations

- The image was not rebuilt in this session; the build-time `ffmpeg -version`
  check is the guard that will catch a broken binary on the next
  `docker compose up -d --build`.
- `ffmpeg` is GPL-2.0-or-later in the conda-forge build; this only matters if
  the distribution of the image is subject to copyleft review.
- Thumbnails are still best-effort: a corrupt or unsupported video yields the
  placeholder frame.
